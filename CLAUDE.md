# Репозиторий: документация МойСклад + наши приложения на её API

- `source/` — зеркало официальной документации МойСклад JSON API 1.2 (`moysklad/api-remap-1.2-doc`).
  Это справочник, а не наш код: не правь его, если об этом прямо не попросили, — иначе
  обновления из upstream начнут конфликтовать. Искать по нему — скил `moysklad-api`.
- `apps/` — наши приложения поверх API. Сейчас там `apps/shipments-hub` — хаб отгрузок:
  события по отгрузкам → автоматизации (первая — УПД покупателю). Устройство — его README.

## Скилы

- `moysklad-api` — любой код, который ходит в api.moysklad.ru: сверяйся с документацией, не с памятью.
- `new-automation` — новая автоматизация в хабе («когда отгрузка …, сделай …»).
- `deploy-hub` — деплой на Dockhost, переход из dry-run в боевой режим, неисправности.

## Правила

- Перед коммитом в `apps/shipments-hub`: `python3 -m pytest -q` и `ruff check .` — оба зелёные.
  Зависимости: `python3 -m pip install -r apps/shipments-hub/requirements-dev.txt`.
- Секреты (токен МойСклад, SMTP, Telegram) — только в переменных окружения. Не в коде,
  не в `config.yaml`, не в коммитах, не в чате.
- Всё, что отправляет что-то наружу (клиентам, в чаты), начинается в `HUB_DRY_RUN=1`.
- Из облачной сессии сеть до api.moysklad.ru обычно закрыта. Проверяй на поддельном МойСклад
  (`apps/shipments-hub/tests/fake_moysklad.py`) и честно пиши, что живой прогон не делался.
  Ответы API не выдумывай.
- Коммиты — коротко и по-русски, что изменилось для пользователя.
