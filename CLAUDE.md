# moysklad-hub

Сервис автоматизаций МойСклад: заказы, отгрузки, контрагенты — события → автоматизации-плагины.
Устройство — `docs/ARCHITECTURE.md`, обзор и команды — `README.md`.

## Скилы

- `moysklad-api` — любой код, который ходит в МойСклад: сверяйся с `docs/moysklad-api`, не с памятью.
- `new-automation` — новая автоматизация или новый тип сущности.
- `deploy-hub` — Dockhost, переменные, переход из dry-run в боевой режим, неисправности.

## Правила

- Перед коммитом: `python3 -m pytest -q` и `ruff check .` — оба зелёные. Меняешь
  `hub/storage` или конкурентность — прогони и на PostgreSQL (`HUB_TEST_DATABASE_URL`, см. README).
- `docs/moysklad-api/` — копия официальной документации, руками не правится;
  обновление — `update_docs.py`.
- HTTP к МойСклад — только через `hub/moysklad/`. Автоматизации пишут в МойСклад только через
  `ctx.set_state` / `ctx.set_fields`, наружу ходят только через `ctx.channels` — так работает dry-run.
- Секреты (токен МойСклад, SMTP, Telegram) — только в переменных окружения: не в коде,
  не в `config.yaml`, не в коммитах и не в чате. Если пользователь хочет дать токен, предложи
  добавить его в окружение (переменная `MOYSKLAD_TOKEN`), а не присылать в чат.
- Всё, что отправляет клиентам или меняет МойСклад, начинается с `HUB_DRY_RUN=1`.
- Из облачной сессии сеть до api.moysklad.ru обычно закрыта. Проверяй на поддельном МойСклад
  (`tests/fake_moysklad.py`) и честно пиши, что живой прогон не делался. Ответы API не выдумывай.
- Коммиты — коротко и по-русски, что изменилось для пользователя.
