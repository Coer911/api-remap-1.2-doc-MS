# Деплой хаба отгрузок

Хаб — один Docker-контейнер: веб-сервер, воркер очереди и опрос в одном процессе. Поэтому
реплика ровно одна: две реплики начнут делить очередь и могут отправить документ дважды.

## Перед релизом

```bash
cd apps/shipments-hub && python3 -m pytest -q          # всё зелёное — иначе не выкатываем
docker build -t shipments-hub . && docker run --rm -e MOYSKLAD_TOKEN=x -p 8080:8080 shipments-hub
curl localhost:8080/healthz                             # {"ok": true, ...}
```

## Dockhost

Так же, как прайс `Coer911/ccr-price-standalone` (у него `Dockerfile` + `dockhost.yaml`
в корне): проект из Git-репозитория с Push-to-Deploy, образ собирается из `Dockerfile`.

- Корень сборки — `apps/shipments-hub` (там `Dockerfile`, `dockhost.yaml`, `.dockerignore`).
  Если панель не даёт выбрать подпапку, вынеси `apps/shipments-hub` в отдельный репозиторий —
  код от этого не меняется.
- Порт контейнера — `8080` (переменная `PORT`).
- Переменные окружения — список с пояснениями в `.env.example`. Секреты (`MOYSKLAD_TOKEN`,
  `SMTP_PASSWORD`, `TELEGRAM_BOT_TOKEN`, `HUB_API_KEY`, `HUB_WEBHOOK_SECRET`) — только в панели,
  не в git и не в чате.
- Постоянный диск — смонтировать в `/data` (там `hub.sqlite3`: очередь, журнал, курсор опроса).
  Без диска хаб работает, но журнал обнуляется на каждом релизе; от повторной отправки тогда
  защищает только доп. поле `mark_attribute` в МойСклад — не выключай его.
- Домен → `HUB_PUBLIC_URL` (https).

Схему `dockhost.yaml` в этом репозитории подтверждают только поля, работающие у прайса
(project, containers, name, image, replicas, resources). Порт, переменные и диск задаются
в панели. Не придумывай новые поля — сверься с документацией Dockhost или спроси пользователя.

## После релиза — по порядку

Команды выполняются в консоли контейнера (или локально с теми же переменными):

```bash
python -m hub check              # токен, статус, шаблон УПД, доп. поле, вебхуки, каналы
python -m hub setup              # создать доп. поле «УПД отправлен», если его нет
python -m hub webhooks install   # вебхуки CREATE/UPDATE/DELETE на отгрузки → хаб
python -m hub journal            # что происходило
```

1. Первые дни — `HUB_DRY_RUN=1`: хаб пишет в журнал, что и кому отправил бы, но не отправляет.
   Проверь журнал и `python -m hub run send_upd <номер>` на 2–3 реальных отгрузках.
2. Всё верно — `HUB_DRY_RUN=0` и перезапуск. Пробные записи не мешают: у боевого режима свои
   ключи, а старые отгрузки без новых изменений никто не тронет.
3. Задай `HUB_ALERT_CHAT`, чтобы узнавать о сдавшихся автоматизациях из Telegram, а не от клиентов.

## Если не работает

| Симптом | Где смотреть |
|---|---|
| `check`: токен не работает | токен сотрудника, права на отгрузки/печать/доп. поля |
| вебхуки не приходят | тариф МойСклад платный? `webhooks list`; секрет в URL совпадает с `HUB_WEBHOOK_SECRET`; домен отдаёт https |
| вебхуки отключились сами | МойСклад отключает их, если больше 7 из последних 10 дней хаб отвечал только ошибками (`_restrictions.md`); почини и `webhooks install` |
| УПД не ушёл | `journal --status failed` / `skipped`: нет e-mail у контрагента, статус назван иначе (`states`), SMTP |
| отправилось дважды | две реплики? пропал диск и выключен `mark_attribute`? |
| 429 в логах | другие интеграции съедают лимит 45/3 с; хаб сам подождёт, но проверь соседей |
