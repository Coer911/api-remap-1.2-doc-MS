# Деплой moysklad-hub

Один образ, роль задаёт `HUB_ROLE`. Начинать с одного контейнера `all` на SQLite.
Как растёт нагрузка — `docs/ARCHITECTURE.md`, раздел «Масштабирование».

## Перед релизом

```bash
python3 -m pytest -q && ruff check .
docker build -t moysklad-hub . && docker run --rm -e MOYSKLAD_TOKEN=x -p 8080:8080 moysklad-hub
curl localhost:8080/healthz
```

## Dockhost

Так же, как прайс `Coer911/ccr-price-standalone`: проект из GitHub-репозитория,
Push-to-Deploy, образ из `Dockerfile` в корне.

- Порт контейнера `8080`.
- Переменные — из `.env.example`. Секреты (`MOYSKLAD_TOKEN`, `SMTP_PASSWORD`,
  `TELEGRAM_BOT_TOKEN`, `HUB_API_KEY`, `HUB_WEBHOOK_SECRET`) — только в панели.
- Постоянный диск — в `/data` (там `hub.sqlite3`). Нет диска — подключи PostgreSQL
  (`HUB_DATABASE_URL=postgresql://…`), иначе журнал обнуляется на каждом релизе.
  От повторной отправки и тогда защищают отметки `mark_field` в МойСклад — не выключай их.
- Домен → `HUB_PUBLIC_URL` (https).
- Реплика одна, пока база SQLite.

Подтверждены только поля `dockhost.yaml`, которые работают у прайса (project, containers,
name, image, replicas, resources). Порт, переменные и диск задаются в панели. Новые поля
не придумывай: сверься с документацией Dockhost или спроси пользователя.

## После релиза — по порядку

В консоли контейнера (или локально с теми же переменными):

```bash
python -m hub check              # токен, статусы, шаблоны, доп. поля, вебхуки, каналы
python -m hub setup              # доп. поля-отметки, которых не хватает
python -m hub webhooks install   # вебхуки на нужные типы → хаб
python -m hub journal
```

1. Первые дни `HUB_DRY_RUN=1`: журнал показывает, что ушло бы и что записалось бы в МойСклад.
   Проверь `python -m hub run <автоматизация> <номер>` на 2–3 реальных документах.
2. Всё верно — `HUB_DRY_RUN=0` и перезапуск. У пробных прогонов свои ключи, боевым они не мешают.
3. Задай `HUB_ALERT_CHAT`, чтобы о сдавшихся автоматизациях узнавать из Telegram.

## Масштабирование

PostgreSQL обязателен. Тот же образ, отдельные контейнеры:
`HUB_ROLE=api` (сколько угодно), `worker` (сколько угодно), `scheduler` (1–2: работает
один, второй ждёт). На SQLite хаб откажется стартовать в раздельной роли — это намеренно.
Лимит МойСклад общий на токен: при N воркерах с одним токеном — `MOYSKLAD_RPS ≈ лимит / N`.

## Если не работает

| Симптом | Где смотреть |
|---|---|
| `check`: токен не работает | токен сотрудника, права на нужные документы, печать, доп. поля |
| вебхуки не приходят | тариф МойСклад платный? `webhooks list`; секрет в URL = `HUB_WEBHOOK_SECRET`; https отвечает |
| вебхуки отключились сами | больше 7 из 10 дней хаб отвечал ошибками (`_restrictions.md`): почини, `webhooks install` |
| документ не ушёл | `journal --status failed` / `skipped`: нет e-mail, статус назван иначе (`states`), SMTP |
| ушло дважды | две реплики на SQLite? пропала база и выключен `mark_field`? |
| много 429 | лимит токена пользователя сейчас 15/3 с (с 01.12.2026 — 11); соседние интеграции на том же пользователе; `MOYSKLAD_RPS` |
| очередь растёт (`/api/stats`) | воркер не успевает: PostgreSQL и `HUB_ROLE=worker` ×2 |
