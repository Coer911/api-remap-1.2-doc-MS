# Новая автоматизация в хабе отгрузок

Хаб уже умеет главное: узнаёт об изменениях отгрузок (вебхук + опрос), грузит свежую
отгрузку, не запускает одно и то же дважды, повторяет сбои и шлёт алерт. Автоматизация —
это только решение «надо ли» и сама работа. Не изобретай свою очередь, планировщик или
HTTP-клиент: всё это уже есть и протестировано.

Устройство описано в `apps/shipments-hub/README.md`, интерфейс — в docstring
`apps/shipments-hub/hub/automations/__init__.py`. Факты об API — скил `moysklad-api`.

## 1. Договорись о четырёх вещах

Спроси, если из запроса не ясно — от этого зависит, не уйдёт ли что-то клиенту дважды:

1. **Когда** — статус отгрузки, юрлицо, канал продаж, сумма, доп. поле.
2. **Сколько раз** — раз на отгрузку (по умолчанию) или раз на каждый статус/изменение.
   Это ключ идемпотентности `key()`.
3. **Что и куда** — какой документ/текст, в какие каналы (email, telegram, webhook).
4. **Как отметить** — доп. поле в МойСклад (видно менеджерам и спасает от повтора, если база хаба
   потеряется) или достаточно журнала хаба.

## 2. Напиши модуль

Скопируй `hub/automations/_template.py` в `hub/automations/<имя>.py` (имя — snake_case,
оно же ключ в `config.yaml`).

- Все параметры с безопасными значениями — в `defaults`. Неизвестный параметр в config.yaml
  хаб отвергнет при старте — это защищает от опечаток.
- `wants()` — только проверки по уже загруженной отгрузке, без запросов в API: он вызывается
  на каждое событие.
- `run()` — работа. Наружу ходи только через `ctx.channels` (так работает `HUB_DRY_RUN`)
  и `ctx.ms` (лимиты МойСклад). Верни короткий итог для журнала.
- `raise Skip("почему")` — когда делать нечего и повторять бессмысленно (нет e-mail).
  Любое другое исключение — повтор через 1 мин, 5 мин, 30 мин, 2 ч, 6 ч, потом алерт.
- Несколько каналов — оборачивай каждый в `ctx.step_done/mark_step` с ключом
  `ctx.run_key(self, shipment)`, как в `send_upd.py`: тогда после сбоя второго канала первый
  не повторится.
- Печать любого документа: `tpl = await ctx.ms.find_template("ТОРГ-12")`,
  `await ctx.ms.export("demand", id, tpl, "pdf")`. Ссылка: `await ctx.ms.publish(...)`.
- Нужна не отгрузка, а заказ/счёт — в `hub/ingest.py` добавь тип в `ENTITIES` и опрос,
  в автоматизации укажи `entity`, а в движке — загрузку этого типа. Это изменение ядра:
  сделай его отдельным шагом с тестами.

## 3. Включи в config.yaml

```yaml
automations:
  <имя>:
    enabled: true
    state: "Отгружен"
```

## 4. Тест на поддельном МойСклад

Добавь `tests/test_<имя>.py` по образцу `tests/test_send_upd.py`: фикстуры `fake` и `make_hub`,
`fake.add_demand(...)`, `accept_webhook(...)`, `await hub.tick()`, проверки по
`hub.channels.emails / documents / hooks`. Минимум проверь: срабатывает при нужном условии,
не срабатывает при чужом, второй раз не отправляет, сбой канала уходит в повтор.

```bash
cd apps/shipments-hub && python3 -m pytest -q
```

## 5. Обкатка без риска

Боевой запуск — только после пробного: `HUB_DRY_RUN=1` и
`python -m hub run <имя> <номер отгрузки>` — покажет, что бы ушло и кому. Пробные прогоны
не блокируют настоящую отправку. Потом `python -m hub check` и деплой (скил `deploy-hub`).

## 6. Опиши

Добавь строку в таблицу автоматизаций в `apps/shipments-hub/README.md`: имя, когда, что делает,
куда отмечает.
